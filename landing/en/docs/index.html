Bitrox ServiceTracker Setup & Architecture Guide

This guide provides step-by-step instructions for deploying Bitrox ServiceTracker in local development and production environments, configuring the MySQL database, and setting up the read-only Snipe-IT REST API synchronization.

1. System Prerequisites

  • Node.js: v18.0.0 or higher (LTS recommended)
  • MySQL / MariaDB: v8.0+ with InnoDB storage engine and utf8mb4 encoding
  • Package Manager: npm or yarn
  • Git: To clone and update the repository
  • (Optional) Snipe-IT v5.0+ with API access enabled — note that all ServiceTracker modules work standalone without Snipe-IT.

2. Quickstart (5 Steps)

Step 1: Clone the Repository

git clone https://github.com/KingLyzer/bitrox-service-tracking.git
cd bitrox-service-tracking

Step 2: Install Dependencies

npm install

Step 3: Import the Database Schema

Execute the included database_schema.sql file on your MySQL server to initialize the database, default permission matrix, and initial administrator user:

mysql -u root -p < database_schema.sql

Step 4: Configure Environment Variables

Copy .env.example to .env and fill in your database credentials and secret key:

cp .env.example .env

Step 5: Build Assets and Start Server

npm run build
npm start

By default, the server listens on http://localhost:9999.

Security Notice: The default credentials are Username: admin / Password: admin123. You must update your password in Settings immediately after first sign-in.

3. Snipe-IT API Integration

To enable automatic lookups for employee assets and printer devices:

  1. Sign in to your Snipe-IT dashboard: navigate to Admin → Manage API Keys.
  2. Generate a new Personal API Access Token and copy the secret key.
  3. In Bitrox ServiceTracker, open Settings → General Settings → Snipe-IT Integration:
    • Snipe-IT URL: https://inventory.yourcompany.com
    • API Token: Paste your Bearer token.
  4. Click Save. The background synchronization worker will query the Snipe-IT endpoints and populate the local cache tables. Snipe-IT assets remain strictly read-only.

4. Production Deployment with PM2

To run ServiceTracker continuously and auto-restart on system reboot:

npm install -g pm2
pm2 start server/server.js --name "servicetracker"
pm2 save
pm2 startup

5. Security Checklist

Recommended actions for securing your production deployment:

  • Change the default admin credentials immediately after initial login via Settings → Users.
  • Set up a reverse proxy (Nginx or Caddy) with an SSL/TLS certificate (Let's Encrypt).
  • Restrict database network access to localhost (127.0.0.1) only.
